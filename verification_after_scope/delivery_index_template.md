# Индекс выдачи решения

Это шаблон выдачи, а не итоговый отчёт. На момент проверки завершён `reference`, `balanced` ещё выполняется. По запросу пользователя сравниваются только эти два варианта; `old` и `ensemble_old` пропущены. Итоговые метрики и экономия здесь не подставлены.

## Что передать

Все пути ниже указаны от корня проекта.

| Папка | Содержимое | Готовность на момент проверки |
| --- | --- | --- |
| `data/processed/metro52_full_day_20261009/` | Полная запись текущей кампании: результаты, контракты, движение, пассажиры, прогнозы, решения, объяснения, журналы и итоговые отчёты | Кампания выполняется |
| `data/processed/metro51_inputs_20261009/` | Подготовленные входы, `source_frame.parquet`, признаки и таблицы потоков, LightGBM, три GRU, persistence, параметры стекинга, контракты и SHA-256 | Есть; повторное обучение не требуется |
| `data/processed/metro48_daily_fifo_20261009_v7/runs/DAILY_FIFO_S1_7/` | Исходное состояние движения и пассажиров для воспроизведения | Есть |
| `data/processed/metro52_readiness_20261009/` | JUnit, stdout, проверки модели, интерфейса, vendor, экспортированной копии и последующих исправлений | Есть; пополняется новыми проверками |
| `data/processed/metro52_publish_20261009/export/` | Исходники, тесты, документация, интерфейс, vendor, необходимые данные и веса, версии зависимостей, безопасный `.env.example`, манифест файлов | Есть; окончательные результаты текущей кампании добавляются отдельно |

В каждой завершённой arm-папке нужны `result.json`, `contract.json`, `common_scenario.json.gz`, `execution_sources/` и `runs/RUN51_*/`. В run-папке сохраняются `movement_input.json`, `motion.json`, `profiles.json`, `groups.json.gz`, `passenger_checkpoint.json.gz`, `summary.json`.

В `balanced/controller/` сохраняются `raw_forecast_*.json`, `forecast_*.json`, `decision_*.json`, `resume_*.json.gz`; в `balanced/explanations/` — `facts_*.json` и `explanation_*.json`. Для восстановления также сохранить `events.jsonl`, `*.log`, `logs/`, `status.json`, `campaign_scope.json`, `orchestration_handover/`. Процессные ID и записи этапов являются историей запуска, а не обещанием работы на другом ПК.

## Ожидаемые итоговые файлы

Следующие файлы текущей кампании ещё ожидаются. Их наличие и статус надо проверить после завершения; пустой CSV не означает нулевой поток или нулевую ошибку.

| Путь внутри кампании | Назначение |
| --- | --- |
| `review/report.pdf`, `review/report.html`, `review/report.md` | Итоговый отчёт: безопасность, очереди, ожидание, загрузка, экономика и объяснения |
| `review/comparison.json`, `review/verification.json` | Метрики, независимые проверки, статус допустимости, хеши файлов и проверка PDF |
| `review/dispatcher.html` | Просмотр решений и объяснений без запуска модели |
| `review/economics.csv`, `review/per_train.csv` | Стоимость и дельта без СР/КР и с СР/КР, по парку и каждому составу, за день и в годовом сценарии |
| `review/local_cohorts.csv`, `review/waiting_budgets.csv`, `review/local_waiting.csv`, `review/comfort.csv` | Локальные непосадки, ограничения ожидания, очереди и загрузка вагонов |
| `review/decisions.csv`, `review/explanations.csv`, `review/post_execution_forecasts.csv` | Действия оптимизатора, ответы LLM и оценка прогнозов после исполнения |
| `review/incident_probes.csv`, `review/input_inventory.csv` | Диагностические остановки и перечень исходных файлов с размерами и SHA-256 |
| `review/cost.png`, `review/local_misses.png` | Графики стоимости и локальной непосадки |
| `review/pdf_renderer.log`, `review/pdf_text.txt` | Журнал создания PDF и извлечённый текст для проверки |
| `forecast_review/report.json`, `forecast_review/report.md`, `forecast_review/predictions.csv` | Ошибка сохранённых прогнозов; будущий факт используется только для оценки |
| `forecast_review/by_arm.csv`, `by_station.csv`, `by_horizon.csv`, `by_native_slot.csv`, `by_origin_mode.csv`, `by_peak.csv`, `by_station_horizon_peak.csv` | Разрезы ошибки модели; все перечисленные CSV находятся в `forecast_review/` |

| `incidents/stop_3/`, `incidents/stop_8/`, `incidents/stop_15/` | `result.json` каждого случая; при завершённом расчёте также `movement_input.json.gz`, `passenger_checkpoint.json.gz`, `queue_by_station.csv` |

PDF создаётся из HTML через Edge/Chromium/Chrome; установленный Edge найден. Экспорт проверяет страницы, SHA-256 и наличие текста про безопасность, обе колонки СР/КР и погрешности ±5%/±20%. Успех подтверждается `review/verification.json`, а не одним существованием PDF. Служебный `review/pdf-browser-profile/` передавать не требуется.

## Проверки и перенос

Сохранены полная проверка экспортированной копии: 2080 тестов без ошибок и пропусков, 19 тестов Streamlit, vendor: 529 тестов и 643 subtests. Это проверки до последнего исправления отбора arm-папок в отчёте; для него отдельно сохранены 34 успешных report-теста в `tests/report/final_junit.xml`. Эти наборы нельзя складывать как независимые тесты. Подробности находятся в `tests/export/summary.json`, `tests/ui/verification.json`, `tests/vendor/portable_final_evidence.json` и соответствующих stdout/JUnit.

Ещё нужны итоговый независимый аудит двух завершённых вариантов, проверка PDF, полноты фактов/объяснений и открытие **новой завершённой** записи в Streamlit. Полный день в интерфейсе ранее проверен на сохранённой старой записи; это не проверка результата нынешнего `balanced`. Диагностика одного ответа LLM находится в `tests/llm_diagnostic/result.json`; она не объясняет автоматически все шаблонные замены.

Streamlit работает: <http://localhost:8501>, health при проверке — `ok`. В поле «Папка эксперимента» указать `data/processed/metro52_full_day_20261009` или абсолютный путь к его копии. «Обновить журналы» читает очередную запись; повторное моделирование не запускается. Отсутствующие прогнозы не подменяются выдуманными.

Для нового запуска использовать Python 3.12 и проверенный `requirements-runtime.txt`, включая CPU Torch. Веса и подготовленные данные включены в экспорт; загрузка ансамбля и Replay из экспортированной копии проверены. Исходный ансамбль имеет шаг 30 минут, адаптер обновляется каждые 15 минут; срезы :15/:45 остаются экспериментальными. При клонировании сохранить байты исходников: `core.autocrlf=false`, на Windows также `core.longpaths=true` и короткий путь проекта.

Готовые PDF/HTML/CSV и Replay можно читать из перенесённой папки. Исходные контракты текущего запуска содержат абсолютные пути к файлам и модели: перенос папки сам по себе не подтверждает повторный независимый аудит на другом ПК. Контракты не переписывать; новый эксперимент создаёт собственные пути и доказательства. Проверка такого переноса нынешнего итогового аудита ещё не выполнена.

В публичную выдачу не включать `.env`, исходный рабочий `.env.example`, API-ключи и заголовки авторизации. В экспортированном шаблоне только заглушки. Перед добавлением новых результатов нужен повторный поиск секретов; текущие журналы нельзя объявлять проверенными заранее. Расчётная дельта считается допустимой экономией только после проверки ограничений; годовая оценка остаётся сценарием, реальная экономия бюджета не доказана.
