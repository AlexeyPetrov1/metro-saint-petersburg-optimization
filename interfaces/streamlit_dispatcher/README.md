# Интерфейс диспетчера в Streamlit

Отдельная оболочка к существующему симулятору красной линии. Модель, оптимизатор,
движение и посадка пассажиров остаются в основном проекте. Оболочка читает их
сохранённые результаты и не запускает расчёты при переключении экрана.

Основа оформления и проигрывателя:
[sirius-subway_simulation](https://github.com/KovalevNikolay710/sirius-subway_simulation/tree/2bbcdb97dda3a2ba2f12490919bb3fdf57ce58ea),
ветка `dev`, версия `2bbcdb97dda3a2ba2f12490919bb3fdf57ce58ea`.
Исходные файлы сохранены без правок в `upstream/`; их контрольные суммы находятся
в `upstream.json`. Используется браузерный проигрыватель и оформление. Внешний
симулятор и его алгоритм управления не подключаются.

## Запуск

Из корня `C:\Users\lesha\HackathonSPB`:

```powershell
& .\interfaces\streamlit_dispatcher\start.ps1
```

Открыть <http://localhost:8501>. Порт можно изменить: `start.ps1 -Port 8502`.
При первом запуске на другом компьютере создать отдельное окружение:

```powershell
python -m venv interfaces/streamlit_dispatcher/.venv
& .\interfaces\streamlit_dispatcher\.venv\Scripts\python.exe -m pip install -r interfaces/streamlit_dispatcher/requirements.txt
```

Основное окружение проекта не меняется. Путь к кампании можно указать в боковой
панели или перед запуском задать `$env:METRO_CAMPAIGN_DIR = 'полный путь'`.
По умолчанию открыт эксперимент `metro51_balanced_pilot_20261009_v2`, вариант
`balanced`, время 08:00 МСК. Незавершённый вариант доступен только до последнего
сохранённого состояния. Для него положение составов восстанавливается из
расписания; пассажиры берутся из фактического журнала этого прогона.

## Экраны

- **Прогноз:** входы через турникеты за 15 минут, q10/q50/q90, известные к выбранному
  времени наблюдения, очереди по направлениям и пассажиры в каждом вагоне.
- **Симулятор:** ускоренная перемотка записи, карта загрузки, положение составов,
  очереди, текущий прогноз и решение. Все эти панели следуют за часами проигрывателя.
- **Оптимизатор:** действие, статус проверок, варианты и сохранённое объяснение
  YandexGPT либо шаблонная замена. Полный пакет доступен отдельно.
- **Данные:** источники и выгрузка состояния выбранного момента.

Выпуски прогноза выбираются по времени публикации и доступности признаков.
Будущие выпуски при перемотке назад не используются. Между выпусками действует
последний доступный прогноз; нейросеть не вызывается каждую секунду.
Историческая замена для отдельных станций отмечается явно.

Входы, очередь на платформе и пассажиры в вагонах отображаются отдельно.
Состояние в выбранную секунду соответствует сохранённому снимку: события ровно
на этой границе ещё не включены. Это сохраняет согласованность с данными,
которые видел оптимизатор и которые вошли в объяснение решения.
Распределение пунктов назначения и движение относятся к принятому сценарию
симулятора. Карта загрузки показывает максимальный вагон в составе относительно
150 пассажиров; это не прогноз загрузки перегонов из внешнего репозитория.

`KEEP` с непрошедшими проверками сохраняет свой статус. Интерфейс не выдаёт
такое действие за разрешённое и не рассчитывает экономию самостоятельно.
Для объяснений используются уже сохранённые ответы, поэтому открытие интерфейса
не расходует запросы YandexGPT. Большие объяснения сокращены на карточке, полный
ответ сохранён на странице оптимизатора.

Кнопка «Обновить журналы» перечитывает новые файлы отдельно работающего прогона.
Она не запускает прогон. Сам проигрыватель работает в браузере без повторного
расчёта модели, оптимизатора или пассажиров.

## Проверка

Из корня проекта:

```powershell
& .\interfaces\streamlit_dispatcher\.venv\Scripts\python.exe -m pip install -r interfaces/streamlit_dispatcher/requirements-dev.txt
& .\interfaces\streamlit_dispatcher\.venv\Scripts\python.exe -m pytest interfaces/streamlit_dispatcher/tests/test_adapter.py interfaces/streamlit_dispatcher/tests/test_app.py -q
```

После запуска сервера проверить браузер и все страницы:

```powershell
& .\interfaces\streamlit_dispatcher\.venv\Scripts\python.exe -m pytest interfaces/streamlit_dispatcher/tests/test_browser.py -q
```

Для браузерных тестов используется установленный Edge; при его отсутствии
установить Chromium командой `python -m playwright install chromium` в окружении
интерфейса. Проверки используют готовые журналы и не запускают моделирование.
Снимки экранов и результаты проверки находятся в `artifacts/`.
