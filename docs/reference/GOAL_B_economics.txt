Общий контекст
Вы разрабатываете один модуль репозитория четвёртого участника хакатона по первой линии метро Санкт-Петербурга. Человек 2 владеет данными и прогнозом, человек 3 — общими схемами, распределением поездок, симулятором и экраном, человек 4 — решениями и экономикой. Не создавайте их компоненты заново.
Сначала прочитайте актуальные AGENTS.md и README репозитория, общий контракт и приложенный план. Имена функций ниже — предложение интерфейса; согласованные схемы репозитория имеют приоритет по форме, но противоречия в смысле нужно явно зафиксировать.
Подтверждено для кейса: 113 секунд минимального интервала, 8 вагонов, норма 120 человек на вагон, максимум 53 состава именно на линии, два депо. 99 минут оборота — ориентир источника. Резерв 4 состава в файле назван идеальным, фактическая доступность неизвестна. Времена 7/30 минут из переписки и 15–20 минут из файла имеют конфликтующую семантику: не складывать или выбирать их молча.
120 суток 15-минутных входов — основной реальный спрос; это не моментная численность и не готовая загрузка поездов. OD, пересадки и распределение по вагонам требуют сценариев. Денежные ставки не заданы. Нельзя выдавать учебные коэффициенты за рублёвую экономию.
После фиксации схем работайте только в своей области файлов. Общие схемы меняет координатор с человеком 3, CLI и зависимости — работа E. Данные API не нужны для автономной реализации. Заглушки разрешены для программных проверок и обязаны иметь evaluation_mode=fixture.
Ограничения физики нельзя компенсировать штрафом. Unknown не равен passed. Все планы сравниваются на одном спросе и начальном состоянии. Очереди и обязательства не исчезают в конце 120 минут. Сохраняйте источники и версии; не применяйте реальные команды к системам метро.
Минимум инфраструктуры: Python-пакет, чистые функции, JSON/Parquet и pytest. Не добавляйте сервер или LLM без необходимости. Пройдите значимые проверки своей функциональности, передайте точные команды запуска и ограничения. Не утверждайте, что интеграционные проверки выполнены, если использовали заглушку.

GOAL 14 Работа B Экономический модуль

Цель: получить воспроизводимую разницу расходов между двумя Evaluation при одинаковой границе расчёта. Файлы: economics.py, config/costs и собственные тесты. Входы: база, кандидат, ставки, период и версия модели. Выход: постатейный CostBreakdown со статусом confirmed/assumed/partial/unknown.

Порядок действий

- Определить натуральные показатели: пассажирские и непассажирские поездо-км, вагоно-км по типам, часы движения/остановок/отстоя, оплачиваемые человеко-часы, кВт·ч при наличии модели, события ввода/вывода.

- Разобрать МО-I как HTML в кодировке KOI8-R, несмотря на расширение .xls. Взять отдельно колонку линии 1, пассажирский и нулевой пробег; проверить итоги, не подменяя одну единицу другой.

- Для каждой статьи зафиксировать unit, covered_components и accounting_kind. Денежные расходы, начисленный расход ресурса и капитальные вложения не объединять в один нерасшифрованный итог.

- Реализовать только непересекающиеся денежные компоненты. При неизвестной ставке ненулевого количества вернуть частичный результат; при известном нулевом количестве отсутствие ставки не мешает нулевому вкладу.

- Добавить ресурсный расчёт по типу вагона и обслуживанию. До калькуляции цикла выдавать натуральные остатки и доли ресурса без денежной суммы.

- Сравнить цены и задержки в нескольких явно заданных сценариях. При смене знака экономии возвращать границу выгодности и альтернативы.

- Реализовать порог выгодного отстоя и расчёт целых дней. Не годовать перекрывающиеся двухчасовые окна.

Проверки арифметики

Равные планы дают ноль по каждой разнице. Отрицательная экономия сохраняется. Смена рублей на тысячи рублей без пересчёта единиц отклоняется. Восемь вагонов учитываются один раз. Нулевая базовая стоимость даёт savings_pct=null. Неизвестная ставка и ненулевой пробег не дают ноль. Двойной учёт тяги обнаруживается по пересечению covered_components.

Проверить полный учебный оборот: 59,2 поездо-км, 473,6 вагоно-км, 1,65 поездо-часа; добавление маневра уменьшает экономию. При прежней оплаченной смене экономия труда равна нулю. Расходы возврата после 120 минут учитываются. При c_running ≤ c_standby формула не возвращает положительный порог снятия.

Критерий готовности

Любая цифра раскладывается на количество, ставку, единицу, период и источник. Для набора без тарифов формируется полезный отчёт натуральных показателей. Модуль не использует среднюю тарифную себестоимость предприятия в качестве предельной экономии рейса.
