Учебный симулятор GOAL 3.1

`simulation.py`, версия `simulation-v1.1`, исполняет заданные рейсы через очередь событий. Сеть [A → B → C](../examples/simulation/cycle.json) учебная, её параметры не описывают Петербургский метрополитен. Результаты имеют `evaluation_mode=fixture`. Код данных и `economics-v1.1` сохранён, новых зависимостей нет.

Команды PowerShell из корня проекта:

```powershell
& .\.venv\Scripts\python.exe -m simulation run
& .\.venv\Scripts\python.exe -m simulation check
& .\.venv\Scripts\python.exe -m simulation run --output data/processed/simulation_repeat
& .\.venv\Scripts\python.exe -m simulation check --output data/processed/simulation_repeat
& .\.venv\Scripts\python.exe -m pytest -q
```

`run` принимает `--input`, `--costs`, `--output`, сверяет `baseline` с ручным эталоном GOAL 3.1 и сравнивает с `candidate` через экономику. Другие планы доступны через API `simulate(data, plan_id)` и `to_evaluation(result)`. Ошибка расчёта, включая переполнение, даёт код 2 и манифест ошибки. Для записи нужна пустая или принадлежащая симулятору папка; чужие файлы сохраняются. `check` проверяет комплект и все четыре входных SHA-256. Конкурентная запись и аварии файловой системы не проверены.

Вход JSON, схема `1.0`:

| Поле | Содержание |
|---|---|
| `source`, `period_start`, `period_end` | Источник и границы с одинаковым часовым смещением, без долей секунды; дата в примере условная |
| `stations` | `station_id`, `kind=line/depot`, целые неотрицательные `stop_seconds`, `turnaround_seconds`; одновременно оба ожидания не задаются |
| `tracks` | Уникальный `track_id`, `from_station`, `to_station`, положительный `length_km` строкой Decimal, положительный целый `travel_seconds`; обратный путь задаётся отдельно |
| `trains` | Уникальный `train_id`, `train_type`, положительное целое `cars`, `location`, `state`, целое `ready_after_seconds` |
| `plans` | Уникальный `plan_id`, список `trips`: `trip_id`, `train_id`, целое `departure_second`, последовательность `route` из track_id, булево `passenger` |
| `previous_departures` | Контекст перед окном: `track_id` и отрицательное целое `departure_second`; `[]` явно заявляет отсутствие ограничивающих отправлений, пропуск поля оставляет проверку границы неизвестной |
| `max_trains_on_line` | Необязательный положительный целый предел; при отсутствии проверка отмечена `not_configured` |

Секунды отсчитываются от `period_start`. Первое отправление задаёт рейс, следующие вычисляются после прибытия и станционного ожидания. Прибытие равно отправлению плюс `travel_seconds`. На станции применяется заданный оборот либо остановка; разворот без оборота запрещён. Дополнительное ожидание считается отстоем. В исходных остановке и обороте задаётся оставшееся время, исходный отстой означает готовность.

Для исходного движения нужны `location=track_id`, `ready_after_seconds=0`, `initial_movement={arrival_second, passenger}`. Отправление вычисляется до окна, прибытие после начала; отправление участвует в проверке интервала. Начисленный пробег имеет статус `partial`, его часть внутри окна неизвестна. Последовательный расчёт суток не поддерживается.

| Состояние | Значение | Передача в экономику |
|---|---|---|
| `moving` | Поезд проходит направленный перегон | `moving_hours`, train_h |
| `stop` | Обязательная промежуточная остановка | `stop_hours`, train_h |
| `turnaround` | Обязательный оборот на станции | `turnaround_hours`, train_h |
| `standby` | Поезд стоит и готов к следующему заданному отправлению | `standby_hours`, train_h |

Все поезда присутствуют всё окно; сумма непересекающихся состояний равна его длительности. Порядок событий: прибытие, завершение ожидания, отправление, затем train_id, trip_id, номер перегона. Время учитывается на `[start, end)`. В конце окна обрабатываются прибытия и завершения ожиданий, новые отправления остаются обязательствами. Пробег начисляется при прибытии, включая конечный момент, без деления по времени.

Проверяются ссылки, величины, маршрут, положение, перекрытия, ожидания и интервал ≥113 секунд по одному track_id, включая все переданные отправления до окна. Исходно движущиеся поезда не объединяются при одинаковом времени отправления; совпадающая строка истории учитывается как свидетельство того же события. Разные track_id считаются отдельными путями. В местах `line` считаются все состояния; из депо поезд включается при отправлении, исключается при прибытии обратно. Предел относится только к перечисленному парку; полнота реального парка неизвестна.

Адаптер проверяет версию, режим, булевы признаки полноты, границы, балансы времени и пробега, состояния и обязательства. Результаты прежнего `simulation-v1` нужно пересобрать командой `run`. Готовые вагоно-км повторно не умножаются. Только здесь секунды делятся на 3600, с 28 значащими цифрами. `stopped_hours` включает остановки и обороты, отстой передаётся отдельно; совпадение с определениями МО-I не установлено. Энергия, оплаченный труд, подготовка, платежи обслуживания и внедрения неизвестны. Дополнительных начислений через `events` нет.

`obligations_closed` относится только к заданным движениям и ожиданиям. Незавершённые движения, ожидания и будущие рейсы возвращаются как обязательства; экономика отклоняет незакрытые. Обрезанный пробег частичный. `demand_id=passengers-not-modeled` не доказывает равенство обслуживания пассажиров. Операционный статус остаётся `unknown`, `release_authorized=false`.

Выход `data/processed/simulation/` содержит 11 файлов: `*.simulation.json` с журналом, работой, состояниями, обязательствами и проверками по поездам; `*.events.csv`; `*.evaluation.json` для каждого плана. Общие файлы: `control_check.json`, `economic_comparison.json`, `assumptions.json`, `summary.md`, `build_manifest.json`.

Контроль совпал с ручным эталоном: 6 пассажирских поездо-км, 48 вагоно-км, 600 секунд движения, 120 остановок, 240 оборотов, всего 960. В конце состав готов на A, обязательств нет. Кандидат стоит на A 960 секунд. Разница базы и кандидата равна 6 поездо-км, 48 вагоно-км и 600 секундам движения; разница отстоя равна −960 секундам. Денежные расходы и экономия неизвестны (`status=unknown`, `savings=null`). Влияние на пассажиров не проверялось, поэтому сравнение не даёт рекомендации снять поезд.

После [аудита](simulation_audit.md) проходят 150 тестов: 127 прежних и 23 проверки аудита. Независимые проверки охватывают 260 сценариев; нагрузочный пример содержит 60 000 событий. Прежние 14 файлов данных и восемь экономических файлов сохранены; две сборки симулятора дают одинаковые 11 файлов. Доказательства: `data/processed/simulation_audit/verification.json` и `after.xml`.

Пассажиры, прогноз, оптимизация, сигнализация, стрелки, диспетчерские разрешения, реальные энергозатраты, работа персонала, обслуживание и готовность к выпуску пока не проверяются. Сверенные по фото правила и уточнения ЕО сохранены в прежнем реестре, применимость регламента неизвестна.
